## What the author was aiming for — my synthesis (5 lines)

The author wants page shape chosen by what the page contains, not by one house style inherited from the coordinator skill: narrative where the content is the why (goals-and-history), numbered entries where the headline IS the rule (conduct, state, rulings), and a model organized by the subject's own structure where the content is knowledge of an external system (Apple Books).
He values the B-NN ids as stable conversational handles for review and cross-reference, and objects only to the bold headline sentence when it is a label over facts rather than a rule that stands alone — "calorie free" is about the headline, not about the id.
He holds that the skill-creator guidelines are a default, not a universal: these pages substitute for the project memory Claude Code would natively keep machine-locally, so they must live in the repo to reach cloud sessions and other machines, and that purpose licenses departures from the generic skill format.
For B-20/B-21 he wants the general principle — protect the context, know the repository's shape and file sizes so you can judge whole-file vs section reads — stated once with its reason, instead of an enumeration of specific don'ts that all restate the same rule.
And he suspects the geography page has not yet had the treatment the domain page got, which the record confirms: its entries came ~1:1 from the mined corpus and have since been reworded, never re-shaped, except for the fixture section that `cad737e` turned into a model.
