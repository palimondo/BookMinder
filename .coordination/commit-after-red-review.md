# Commit-after-RED: adversarial review

Commissioned by the author 2026-08-14 ("getting pretty meta recursive... There might be alternative ways to achieve project goals"). Reviewer: fresh agent, no stake in the prior design. Every repo claim below was checked against the tree at d33f4ae; citations are file:line.

## Verdict

**Modify.** Keep commit-after-RED as candidate-facing discipline — in CLAUDE.md, the tdd-bdd skill, and the C3 hooks — and keep a red-first detector. But demote F1 from measurement instrument to measured behavior: add harness-side snapshots as the eval's measurement substrate, define red-first process fidelity over the transcript timeline rather than the commit DAG, and score grammar-compliance (instruction-following) separately from red-first-in-time (process fidelity). The current design has two measurement defects the steelman cannot touch: F1's sensitivity co-varies with the experiment's independent variable (non-compliant low-rung candidates produce commit DAGs the T1 detectors cannot inspect, so exactly the rungs designed to fail are the ones where failures go undercounted), and F1 is forgeable (a one-shot implementation followed by selective staging yields a fully compliant DAG — commits order tree states, not authorship). Neither defect argues against the *rule*; both argue against renting the eval's instrument from the subject under measurement.

Process-forcing | the rule + C3 hooks | same rule; but its *measurement* function moves to snapshots | The bet ("rigorous process > one-shotting") is what the enforcement ladder tests — the rule is subject matter, correctly placed. | 4. Measurement resolution | F1-F6 read the candidate's commit DAG | harness snapshots + transcript; candidate DAG demoted to a claim, cross-checked | The load-bearing role fails twice — condition-correlated sensitivity and forgeability — detailed below. |

The author's own recorded premise — "for a product, we would not need a granularity of commits on this TDD cycle level. But for the benchmark, it makes sense" (threads.md:27) — is half true. The benchmark's *task generation* does not need it (eval-design.md:35). The benchmark's *grading* wanted it, and grading is precisely the function that should not depend on candidate behavior.

## The coordinator's conflation hypothesis, attacked both ways

**Where it overstates.** "Degrades the record used to grade everything else" is too broad. T2 runs over the harness-owned JSONL transcript — "no scrollback lossiness in runs we control" (eval-design.md:28) — and T3 judges the transcript and final tree. Neither depends on candidate commits. The final tree is always gradeable. And "grammar absent" is itself a clean top-line result for the discipline question at that rung, not a measurement failure.

**Where it understates.** The real defect is not that the record degrades — it is that it degrades *differentially by condition*, and condition is the experiment's independent variable. Every T1 example in eval-design.md:27 needs commit granularity: RED checkout-and-run, AST-diff of specs *between commits*, `refactor:` commits re-verified, impl edits with no *preceding* spec change. A C0 candidate that one-shots into one commit gives these detectors nothing to inspect, so T1-detectable failure modes are undercounted exactly at the rungs the design expects to fail (eval-design.md:43). The headline failure-modes × conditions matrix (eval-design.md:52) then shows low rungs cleaner than they were — biasing the enforcement-delta estimate, which is the one number the eval exists to produce. An instrument whose sensitivity is a function of the independent variable is not an instrument; it is a confound.

**The second defect: forgeability.** F1's check — "check out spec-introducing commit, run the new test — must fail; successor commit must pass" (eval-design.md:27) — verifies tree states, not authorship order. A candidate that writes spec and implementation together can stage the spec alone, commit (the checkout genuinely fails — the impl is unstaged), then commit the impl. F1 passes; the process was one-shot. T-14's claim that "the log becomes the proof that a falsifier preceded the implementation" (cycle-and-commits.md:9) is therefore wrong as stated: the log is a *claim* that a falsifier preceded the implementation. The only proof is the transcript — a pytest tool call observed failing before the first implementation-file edit. The harness already owns that record.

**A third, smaller problem: the gold references fail the grammar.** eval-design.md:45 uses the author's actual commit sequences as judge references for gold-standard-era stories. The mined corpus era has no commit-after-RED practice — the miners recorded its absence explicitly (v2/day-004.yaml:832, day-005.yaml:592, day-016.yaml:845, day-017.yaml:921, day-020-s2.yaml:649, day-021.yaml:1287), and only four RED-labeled commits exist in the whole history, all 2025-07-13..07-26 (1d1fb34, 32d784b, bd47589, 5125e9c). F1-as-instrument grades candidates by a grammar the reference trajectories do not exhibit. Scope F1 to conditions where the rule was stated, and keep judges from treating reference trajectories as grammar-normative.

## Alternatives adjudicated

**(a) Harness-side shadow snapshots — adopt, as complement not replacement.** Snapshot the tree after every tool call (or every test run), supervisor-side. Guarantees rewind and uniform measurement granularity across all conditions; enables replay-based RED verification (check out snapshot N, run the named spec) independent of any candidate claim. Concrete win for F2: without a RED commit, a weakened assertion never enters the DAG at all — the spec is first committed already-weakened at GREEN, so F2-over-DAG is structurally blind to the exact failure it was mined to catch; F2-over-snapshots sees the strong→weak transition. Implementation note: do it from outside the candidate's view (supervisor rsync/overlayfs or a detached GIT_DIR), *not* as a visible PostToolUse hook — a "bare model" C0 rung with snapshot machinery in settings.json is no longer bare, and the observer effect would contaminate the control. Serves goals 1 and 4 only; goals 2-3 stay with the rule.

**(b) Per-feature commits suffice for rewind — confirmed true.** eval-design.md:35 needs story-boundary checkpoints only; difficulty tiers (greenfield / lapsed-suite / repair) are all era- or story-level. Cycle-level rewind for trial generation is a need no current design element has. Goal 1 is not a justification for the grammar.

**(c) Keep grammar as C2/C3 content, drop F1, grade via F5/F6 + transcript — half right, and the wrong half is fatal.** The demotion instinct is correct; the deletion violates the design's own falsifiability principle: "a rule with no detector and no rubric item is unfalsifiable prose" (eval-design.md:31). C1-C3 state the rule, so something must grade adherence. Dominated by (e), which keeps a cheap deterministic compliance check and adds the transcript check (c) wanted.

**(d) Keep as-is — the steelman, honestly.** The probe value is real (goal 2 holds). No harness machinery needed. The product cost is smaller than the cost list in this review's commission suggests: pre-commit runs only ruff/mypy, not pytest (.pre-commit-config.yaml:15-31), so hooks never fight a RED commit; and outside-in ATDD already keeps a deliberately-red acceptance spec on main mid-feature by design (CLAUDE.md:124), so the bisect predicate and any CI-green-per-commit invariant are *already* conditional — commit-after-RED raises the frequency of red tree states, it does not introduce them. Feature-squash-at-merge reconciles the rest, as the author said. **Rejected anyway**: the steelman defends the rule and the probe, which the modify verdict keeps in full. It has no answer to the condition-correlated sensitivity or the forgeability of F1-as-instrument — those are properties of where the measurement lives, not of the rule.

**(e) Hybrid — the recommendation.** Snapshots (a) carry measurement; the grammar stays as graded behavior; F1 splits into F1a (DAG grammar compliance: does the commit sequence exhibit RED-fail/GREEN-pass — instruction-following signal, cheap, deterministic) and F1b (transcript red-first-in-time: a failing run of the new spec precedes the first implementation edit — process fidelity, ground truth). F1a-pass ∧ F1b-fail is itself a named failure mode — call it retro-staged-grammar, discipline-theater class — and it is exactly the F5 claim-vs-action pattern applied to commits: the DAG is a claim, the transcript is the action.

**(f) git-notes / tags as cycle markers — dominated, discard.** Notes and tags attach to existing commits: they checkpoint nothing (no rewind value), are even cheaper to fabricate post-hoc than a staged commit, and lack the one real mechanical property the RED commit has — freezing the spec baseline before implementation pressure exists. Named for completeness; no tradeoff worth weighing.

## Costs of the recommended design

1. **Harness engineering.** Snapshot capture plus a replay runner. One-time; adjacent to infrastructure the harness already has (it captures final tree, commit DAG, and full JSONL per eval-design.md:45). The genuinely new cost is reconciliation logic across three records — DAG, snapshots, transcript — and that logic *is* the F1a/F1b/retro-staged-grammar detector, so it is spent on signal, not plumbing.
2. **The prose tax stays.** Because the grammar stays, the L-14 carve-outs remain owed: CLAUDE.md:242 ("preserve working state (all tests passing)") still contradicts :127 and :235-238, :132 still says "second commit" for the third (contradiction-ledger.md:152-159), and the skill carries the exception clause (cycle-and-commits.md:9, SKILL.md:16). Under this verdict that price is paid knowingly for goals 2-3, not smuggled in under "the benchmark needs it."
3. **The meta-recursion dissolves rather than resolves.** Measurement no longer depends on the measured rule, so the circularity the author smelled — the benchmark grading compliance with a rule whose main purpose was making the benchmark gradable — is gone. What remains is ordinary self-reference: an eval of instruction-following must state instructions. That is legitimate and unavoidable.
4. **Human-contributor load is unchanged.** The grammar remains a repo rule. If that ever bothers, it becomes a pure product decision with zero eval entanglement — which is precisely the separation this design buys.

## What would change this verdict

- **Pilot data showing both defects are empirically absent.** Run 5-10 C0/C1 trials: if low-rung candidates produce granular commit DAGs anyway (masking rare) *and* no DAG-vs-transcript divergence appears (no retro-staging), keep-as-is wins on simplicity and the snapshot machinery is unearned weight. This is the cheapest decisive experiment and should run before building (a).
- **Snapshots proving infeasible or contaminating.** If the chosen runner cannot snapshot supervisor-side and a visible hook measurably perturbs candidate behavior (A/B one trial with and without), accept the confound, annotate the matrix cells it biases, and keep as-is.
- **The pending 2025 JSONL upload showing real intra-story rewinds.** If the author actually rewound to RED checkpoints mid-story in practice, goal 1 revives at cycle granularity and strengthens the grammar's standing — but does not restore F1-as-instrument, since forgeability is untouched by that evidence.
- **Scope shrinking to C2/C3 only.** Near-universal compliance at high rungs removes the masking confound; the demotion case then rests on forgeability alone, and F1b becomes a nice-to-have rather than a correction.
- **Replace — dropping the grammar entirely — would need evidence this review did not find:** C1-C3 compliance so uniform the probe discriminates nothing, or the author abandoning the process-forcing bet. Neither is in the record.
