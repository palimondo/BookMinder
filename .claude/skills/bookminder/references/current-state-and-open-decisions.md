## Settled rulings — do not reopen them

- **B-61 — Keep the plist API: a deliberate seed, not dead growth.** Do not delete `library.list_books` and `find_book_by_title`, do not report their zero-caller grep as a finding, and do not re-derive the question. They are exercised only by specs and have no caller in `cli.py`, and the author ruled that intentional: they are the seed of the future EPUB content path, since only `Books.plist` carries EPUB file paths, and README documents them as a pre-release library API whose sample matches the real signatures. Treat a smell that has been ruled on as a decision rather than a defect.
- **B-62 — Treat a feature without process provenance as not done.** Redo the filter work that landed after the outside-in lapse through the full outside-in cycle, story card, failing acceptance spec, then inward, rather than keeping the code on the strength of it working: that is the author's revert-and-redo ruling, because "The discipline is the point. The outside-in ATDD." The work is `reopened` on its story cards and annotated in place in TODO.md's Completed Features. Read the plan, its sequencing, and what stays in the tree until the redo starts from TODO.md's In Progress section rather than carrying a copy.

- **B-69 — Leave the cloud display and the cloud filter as they disagree.** `is_cloud` is `ZSTATE in (3, 6)`, so a cloud sample renders with the cloud glyph, but `--filter cloud` on `list recent` matches `ZSTATE = 3` only and `!cloud` matches `ZSTATE != 3`, so a cloud sample displays as cloud yet is excluded by the cloud filter. The 3-only filter is where the author's revert of an unauthorized 3-or-6 widening left it, reverted for landing before approval, not because the wider predicate was ruled wrong. Change neither side without his direction and a spec.
- **B-70 — Leave `path` empty on database-backed books.** `_row_to_book` sets `path=""` pending a `ZASSETID`-keyed correlation with `Books.plist`, and `path` is `NotRequired` on `Book` for the same reason; the domain page records why `ZPATH` is not a substitute. This is design debt the author left as a TODO; do not resolve it as a drive-by.

## Open author decisions — record, do not resolve

- **B-63 — The unspecified borrow.** Fold the missing identity assertion into a repair story when one is started, and never add it as a drive-by edit. `cli.py` imports `SUPPORTED_FILTERS` from the library, the CLI-borrows-library-vocabulary contract, but no spec asserts the identity: the library spec asserts set equality only, and the CLI spec patches the CLI's own attribute, which keeps passing if the CLI grows a private matching literal. The fix's shape is agreed, a one-line identity assertion, `assert cli.SUPPORTED_FILTERS is library.SUPPORTED_FILTERS`, but it is not ruled in and has not landed.
- **B-68 — The silent cloud filter on `list all`.** Leave the missing cloud predicate on `list all` for the author's direction, as a candidate for the filter redo and never a drive-by fix. The shared vocabulary validates `--filter cloud`/`!cloud` for every list command, but `list_all_books` implements only the sample pair, so a cloud value passes validation and silently returns the whole library. Keep it distinct from B-69: that is two predicates disagreeing, this is a predicate missing.

## Standing practice for repairs

- **B-64 — Repair docs and rules in author-approved passes, not on sight.** When you find rot in README, `docs/`, or `AGENTS.md`, verify it, record it as a ledger entry carrying its check command, surface it, and then leave it alone; do not start a repair. The author green-lights a repair pass and that pass consumes the ledger: the README's built-vs-roadmap split, the deletion of a stale toolchain doc, and the `AGENTS.md` corrections all landed that way. Expect every pass to leave residue: retired toolchain names still sit in `docs/`, and a pre-commit test comment still sits in production code.

## The meta layer and this skill's place in it

- **B-65 — Cite `.coordination/` as evidence and history, never as instruction.** It is working substrate, holding the meta-project: the mined rules corpus, the compile policy and eval design, the contradiction ledger carrying the author's rulings, the repair backlog, the process-detector suite, the memory-architecture record, and the tools that validate all of it. Treat nothing produced there as repo rule until the author ratifies it; what he ratifies is landed into the repo's own files. Leave to him whether any of it graduates into `docs/` or `stories/`; that call has not been made. When citing mined records, trust only `quote:` fields as verbatim, because the mining validator checks those fields only and quoted text sitting in any other field was never verified.
- **B-66 — Write durable knowledge into the project's memory, by layer.** When durable knowledge lands, a ruling, a schema verification, a settled decision, write it here or into the artifacts B-60 points at, and nowhere else: the git repo is the only substrate that carries anything across sessions, so knowledge that exists only in a conversation is lost, and knowledge written to a machine-local memory store silently forks the project's memory per machine. This skill is the explicit, loadable encoding of what the project is, the compiled successor of the 2025 session diary, which was the same cure for the same amnesia. Route writes by layer, one source of truth per concern: product-layer in-flight state (backlog order, story progress) goes to `TODO.md` and the `stories/` cards; meta-layer phase state (coordination decisions in flight, run state, review positions) goes to `.coordination/threads.md`; this skill takes only compiled facts the author has ratified. Land a meta-layer ruling's product consequences in the product files, so that a development session never needs the meta record to know what to build; that seam keeps the two layers honest, and `.coordination/memory-architecture.md` holds the reasoning so the split is not re-litigated. Keep this page's claims current rather than letting them fossilize.
