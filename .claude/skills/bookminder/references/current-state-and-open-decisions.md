Do not delete them, do not report the zero-caller grep as a finding, and do not re-derive the question: a smell that has been ruled on is a decision, not a defect.

## Open author decisions — record, do not resolve

- **B-63 — The unspecified borrow.** `cli.py` imports `SUPPORTED_FILTERS` from the library — the CLI-borrows-library-vocabulary contract — but no spec asserts the identity: the library spec asserts set equality only, and the CLI spec patches the CLI's own attribute, which keeps passing if the CLI grows a private matching literal. The fix's shape is agreed — a one-line identity assertion, `assert cli.SUPPORTED_FILTERS is library.SUPPORTED_FILTERS` — but it is not ruled in and has not landed. Fold it into a repair story when one is started; never add it as a drive-by edit.
- **B-68 — The silent cloud filter on `list all`.** The shared vocabulary validates `--filter cloud`/`!cloud` for every list command, but `list_all_books` implements only the sample pair (verified@tree, library.py:171-181) — a cloud value passes validation and silently returns the whole library. Distinct from the display-vs-filter divergence the domain page records under B-44: that is two predicates disagreeing, this is a predicate missing. An accepted-but-unimplemented filter value awaits the author's direction — a candidate for the filter redo, never a drive-by fix.

## Standing practice for repairs

- **B-64 — Doc and rule repair happens in author-approved passes, not on sight.** Rot found in README, `docs/`, or the instruction layer is recorded as a ledger entry carrying its check command and then left alone; the author green-lights a repair pass and that pass consumes the ledger — the README's built-vs-roadmap split, the deletion of a stale toolchain doc, and the instruction-layer corrections all landed that way. Every pass leaves residue behind: retired toolchain names still sit in `docs/`, and a pre-commit test comment still sits in production code. A rot finding is therefore something to verify, ledger, and surface — not a task to start.

## The meta layer and this skill's place in it

- **B-65 — `.coordination/` is working substrate, not repo rule.** It holds the meta-project: the mined rules corpus, the compile policy and eval design, the contradiction ledger carrying the author's rulings, the stamped repair backlog, the process-detector suite, the memory-architecture record, and the tools that validate all of it. Nothing produced there is repo rule until the author ratifies it, and what he ratifies is landed into the repo's own files — so cite `.coordination/` as evidence and history, never as instruction. Whether any of it graduates into `docs/` or `stories/` is his call and has not been made. Blind spot to remember when citing mined records: the mining validator checks `quote:` fields only, so quoted text sitting in any other field was never verified verbatim.
- **B-66 — This skill is the project's memory.** The environment carries nothing across sessions; the git repo is the only substrate, and this skill is the explicit, loadable encoding of what the project is — the compiled successor of the 2025 session diary, which was the same cure for the same amnesia. When durable knowledge lands — a ruling, a schema verification, a settled decision — it belongs here or in the artifacts B-60 points at: knowledge that exists only in a conversation is already lost, and knowledge written to a machine-local memory store is worse than lost, because it silently forks the project's memory per machine. Write-routing by layer, one source of truth per concern: product-layer in-flight state (backlog order, story progress) goes to `TODO.md` and the `stories/` cards; meta-layer phase state (coordination decisions in flight, run state, review positions) goes to `.coordination/threads.md`; this skill takes only compiled facts the author has ratified. A meta-layer ruling must land its product consequences in the product files — a development session must never need the meta record to know what to build; that seam is what keeps the two layers honest, and `.coordination/memory-architecture.md` holds the reasoning so the split is not re-litigated. Keep this page's claims verified or stamped: a fossilized memory is worse than none.
