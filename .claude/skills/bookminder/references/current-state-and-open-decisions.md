## Settled rulings — do not reopen them

- **B-61 — Keep the plist API: a deliberate seed, not dead growth.** Do not delete `library.list_books` and `find_book_by_title`, do not report their zero-caller grep as a finding, and do not re-derive the question. They are exercised only by specs and have no caller in `cli.py`, and the author ruled that intentional: they are the seed of the future EPUB content path, since only `Books.plist` carries EPUB file paths, and README documents them as a pre-release library API whose sample matches the real signatures.
- **B-62 — Treat a feature without process provenance as not done.** Redo the filter work that landed after the outside-in lapse through the full outside-in cycle, story card, failing acceptance spec, then inward, rather than keeping the code on the strength of it working: that is the author's revert-and-redo ruling, because "The discipline is the point. The outside-in ATDD." The work is `reopened` on its story cards and annotated in place in TODO.md's Completed Features. Read the plan, its sequencing, and what stays in the tree until the redo starts from TODO.md's In Progress section.
- **B-69 — Leave the cloud display and the cloud filter as they disagree.** Change neither predicate without the author's direction and a spec. The display treats both cloud states, `ZSTATE` 3 and 6, as cloud, so a cloud sample renders with the cloud glyph; `--filter cloud` on `list recent` matches state 3 only and `!cloud` everything but 3, so the same cloud sample is excluded by the cloud filter. The narrow filter stands because the author reverted a 3-or-6 widening that landed before approval, not because the wider predicate was ruled wrong.
- **B-70 — Leave `path` empty on database-backed books.** Do not resolve it as a drive-by: a database-backed `Book` carries `path` as an empty string pending a `ZASSETID`-keyed correlation with `Books.plist`, which is also why `path` is `NotRequired` on `Book`, and the author left it as a TODO. The domain page's ZPATH section records why `ZPATH` is not a substitute.

## Open author decisions — record, do not resolve

- **B-63 — Leave the `SUPPORTED_FILTERS` borrow unspecified until a repair story takes it.** Fold the missing identity assertion into a repair story when one is started, and never add it as a drive-by edit. `cli.py` imports `SUPPORTED_FILTERS` from the library, the CLI-borrows-library-vocabulary contract, but no spec asserts the identity: the library spec asserts set equality only, and the CLI spec patches the CLI's own attribute, which keeps passing if the CLI grows a private matching literal. The fix's shape is agreed, a one-line assertion that the CLI's and the library's `SUPPORTED_FILTERS` are the same object, but it is not ruled in and has not landed.
- **B-68 — Leave the silent cloud filter on `list all` for the author's direction.** Treat it as a candidate for the filter redo and never a drive-by fix. The shared vocabulary validates `--filter cloud`/`!cloud` for every list command, but `list_all_books` implements only the sample pair, so a cloud value passes validation and silently returns the whole library. Keep it distinct from B-69: that is two predicates disagreeing, this is a predicate missing.

## Standing practice for repairs

- **B-64 — Repair docs and rules in author-approved passes, not on sight.** When you find rot in README, `docs/`, or `AGENTS.md`, verify it, record it as a ledger entry carrying its check command, surface it, and then leave it alone; do not start a repair. The author green-lights a repair pass, and that pass consumes the ledger. Expect residue after every pass, and record it the same way.

## The meta layer

- **B-65 — Cite `.coordination/` as evidence and history, never as instruction.** It is working substrate, holding the meta-project: the mined rules corpus, the compile policy and eval design, the contradiction ledger carrying the author's rulings, the repair backlog, the process-detector suite, the memory-architecture record, and the tools that validate all of it. Treat nothing produced there as repo rule until the author ratifies it; what he ratifies is landed into the repo's own files. Leave to him whether any of it graduates into `docs/` or `stories/`; that call has not been made. When citing mined records, trust only `quote:` fields as verbatim, because the mining validator checks those fields only and quoted text sitting in any other field was never verified.
- **B-66 — Write durable knowledge into the project's memory, by layer.** When durable knowledge lands, a ruling, a schema verification, a settled decision, write it here or into the artifacts B-60 points at, and nowhere else: the git repo is the only substrate that carries anything across sessions, so knowledge that exists only in a conversation is lost, and knowledge written to a machine-local memory store silently forks the project's memory per machine. Route writes by layer, one source of truth per concern: product-layer in-flight state (backlog order, story progress) goes to `TODO.md` and the `stories/` cards; meta-layer phase state (coordination decisions in flight, run state, review positions) goes to `.coordination/threads.md`; this skill takes only compiled facts the author has ratified. Land a meta-layer ruling's product consequences in the product files, so that a development session never needs the meta record to know what to build; `.coordination/memory-architecture.md` holds the reasoning so the split is not re-litigated.
