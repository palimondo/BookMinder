# Repo geography, backlog, and fixture architecture

## Orientation

- **B-20 — Cheapest grounding.** Read what `/hi` and this skill give you before running discovery commands of your own: they already supply the session-start census, and re-deriving project structure by hand is what the author interrupts. Read the production package whole before any task; it is tiny, `bookminder/cli.py` plus `bookminder/apple_books/library.py`, cheaper to read than to guess about, and its current size is one `wc -l` away rather than a number to remember. Read the behavior spec of the whole system with `pytest --spec`. Follow features along the entry chain `bookminder/cli.py` → `bookminder/apple_books/library.py`; everything else is docs, fixtures, or process. Never run unfiltered `find .` or repo-wide line counts, and exclude caches, any vendored venv, and `claude-dev-log-diary/` from every listing or metric: both this repo and BookMind keep a vendored venv in-tree, and the two raw line counts that once produced a "44% code reduction" headline were almost entirely site-packages.
- **B-21 — Land mines.** Never read, grep, commit, or surface `claude-dev-log-diary/`, a large body of hand-curated session transcripts, without explicit user consent, and never reach it indirectly via `git diff`/`git show`/`git log -p` either. Treat a grant as scoped to the exact excerpt and manner named: range-read the named lines rather than ingesting the whole file, because one whole-file read against an explicit line-range grant wasted 10% of context and drew a rebuke, and never read from a background subagent, because the author cannot see or stop what is being read there and he kills those on sight. Expect one day-file to contain several sessions (`^claude` marks each start) and trust only the session-end cost figure. Reference `docs/ui/apple/` screenshots by path and never Read them; they are large binaries. Grep `specs/apple_books/fixtures/All_Books*.swift`, never Read them, and never gitignore or stage them: they are large and deliberately untracked pending curation. Query fixture `.sqlite` files with `sqlite3` and never Read them; they are binary. Execute the `./xs` symlink as the documented tool and never read it as a file; it resolves into the forbidden diary directory. Leave zero-byte fixture files (`401429854.epub`, corrupted_db_user's plist+sqlite) as they are: they are intentional, and the emptiness is the fixture's point rather than damage to repair.
- **B-22 — Spec tree layout.** Place specs by concern, as the tree stands at HEAD: `specs/cli_spec.py`, `specs/cli_formatting_spec.py`, `specs/apple_books/library_spec.py`, `specs/apple_books/library_integration_spec.py`, with fixtures co-located under `specs/apple_books/fixtures/`. Ignore any `unit/integration/acceptance/e2e` directories you find: a 2025 four-layer reorg was reverted wholesale in 2026-08 by checkpoint restore, and those directories can linger only as untracked `__pycache__` residue, never as tracked structure (confirm with `git ls-files specs/`). Never read a coverage gap in subprocess-exercised code as evidence it is untested: `specs/cli_spec.py` drives the CLI via `subprocess` (`sys.executable -m bookminder`), and pytest-cov does not follow child processes.

## Session-transcript preservation

- **B-32 — Native transcript backup (cloud/ephemeral containers only).** `claude-dev-log-diary/jsonl/` preserves full session transcripts in the agentic system's native format, the machine-readable source the day-files only shadow; its README holds the layout and copy commands. When working in an ephemeral container (Claude Code cloud infra), snapshot the session's `.jsonl` file + directory from the harness project store (`/root/.claude/projects/<project>/`) into `jsonl/cloud-<year>/` and commit it, because the container's transcript dies with it. Snapshot (1) always toward session end, when the final branch push is being prepared, and (2) incrementally at natural stable points, after a major phase of work lands or when resuming after a long pause, so that the pause's tail is on disk. Re-snapshot freely, since copies are append-only extensions, and batch the snapshot into an adjacent commit rather than making high-frequency snapshot-only commits. Expect the true tail of a session to arrive with the next session's first snapshot; a transcript cannot contain its own final minutes. Skip all of this in local (non-ephemeral) sessions: the harness store persists there, and the author owns backup timing.

## Backlog and stories

- **B-23 — Backlog practice.** Write stories as YAML cards under `stories/` in story-map columns: `discover` covers listing, filtering, admin access, and error handling; `access` is controlling the Apple Books app; `review` is highlights and notes; `export` is text extraction. Give every card a mandatory `status` from the vocabulary the instruction layer's backlog rules define, and nothing else: no priority or assignee metadata (YAGNI). Take the next story in TODO.md's Discover Column in order rather than offering a menu: the column is a bare list of story paths in implementation order, the order is the plan, and it stays free of emoji, numbering, and per-item rationale. Treat Completed Features as an immutable record of the journey: never reorder or remove entries, annotate a reopened story in place (`[REOPENED: ...]`), list user-visible stories only and no refactorings, and give a doc deletion a one-line breadcrumb with its commit hash. Write parked backlog items with enough of the HOW (mechanism, trigger, expected behavior) that a fresh session can execute them without asking.

## Settled design decisions in the code

- **B-24 — CLI shape.** Keep `main` a Click group and `list` a subgroup declared `@main.group(name="list")` on a function named `list_cmd`; never name the function `list`, which shadows the builtin and breaks `list[Book]` annotations at import time, and fix such name collisions at the source rather than with deprecated typing aliases. Share options between the `recent` and `all` subcommands through the `with_common_list_options` decorator, because Click does not inherit group options. Keep the filter vocabulary to one `--filter` option whose values are attribute names with `!` negation: `cloud`/`!cloud` and `sample`/`!sample` implemented today, with reading status (`finished`, `unread`, `in-progress`) already assigned to the same option by the approved plan, and a single value at HEAD, since multiple filters are deferred future work with no story yet. Do not add `--flag`, `--status`, or `--type`: those were considered and reversed, so reintroducing one reopens a settled decision. Negate with `!` rather than `-` because Click parses a leading `-` as an option, and keep filters orthogonal to list commands because nothing in Apple Books' UI makes them command-specific. Keep `list recent` a deliberate replica of Apple's Continue section, so that an agent consuming the future MCP surface and the human looking at the app share one frame of reference. Keep `--user` as both a real admin feature (examine another user's books) and the test seam; the admin use case is what licenses it in production. Give the CLI no domain knowledge: it passes the raw `--user` string and filter through to the library and delegates path resolution and querying there.
- **B-25 — The Book type.** Keep one `Book` TypedDict with `NotRequired` optional fields, and never add a parallel type for a variant that adds a field. Require only `title` and `author`; `path` and `updated` are `NotRequired` because the type guarantees only what every code path can honestly supply, and the DB-backed path fabricates `path` as `""` (see the domain page's open path-correlation problem). Expect a plain dict from it: TypedDict is a static annotation only, with no attribute access and no runtime key enforcement.

## Fixture architecture

- **B-26 — Synthetic $HOME personas and the front-door seam.** Build integration fixtures as synthetic home-directory trees under `specs/apple_books/fixtures/users/<persona>/` that replicate Apple's container layout path-for-path, each persona encoding a container state observed on a real machine: `test_reader` (full library), `fresh_books_user` (all containers, empty plist, empty-schema sqlite), `legacy_books_user` (containers but no BKLibrary directory), `never_opened_user` (only the OS-created `com.apple.iBooksX` container, holding an empty `BKLibrary` directory and nothing else: no BKAgentService, no plist, no sqlite), `corrupted_db_user` (zero-byte plist and sqlite; give a corruption scenario the full container, or the plist check fires before the sqlite error). Keep the legacy/never-opened split, because it exercises two distinct error paths in `library.py`: a missing `BKLibrary` directory raises "BKLibrary directory not found", an empty one raises "No BKLibrary database found in:", which is why `never_opened_user`'s empty directory is load-bearing and stays tracked by its leaf `.gitkeep`. Enter fixtures through the front door, `--user`: an absolute path is used verbatim as the home directory, a bare name resolves to `/Users/<name>`, `None` to `Path.home()`, exactly three cases, specced in `library._get_user_path`, with no falsy-string case. Pass absolute fixture paths from specs; a relative path is treated as a username and silently rewritten. Use this seam because fixtures through the product's own parameter exercise the real path-construction code, which patching a private module name would bypass; the older module-constant seam (`BKLIBRARY_DB_FILE`-style) survives only with its known limitation, an in-process substitution resolved at import time that cannot cross a subprocess boundary.
- **B-27 — Fixture data discipline.** Give the fixture database the real schema verbatim: dump `.schema ZBKLIBRARYASSET` from a live database, never hand-write a schema. Populate rows only with `specs/apple_books/fixtures/copy_book_to_fixture.sh` (ATTACH DATABASE + explicit column list minus Z_PK, generated from `PRAGMA table_info`), so that every row is a copy of a real, complete book record; never hand-write or hand-edit SQL, because an invented or edited row encodes the agent's beliefs exactly where the spec is supposed to be falsifiable. When a needed state does not exist, leave it to the author: he adjusts a real book in his library and it gets copied. Use the existing scripts (`create_fixture.sh` creates, `copy_book_to_fixture.sh` populates), and when a script fails, debug the script. Never make a script delete; cleanup is a deliberate human act. In scripts, name the parameter variable `FIXTURE_USER`, never `USERNAME` (a zsh special parameter that silently shadows the argument); SQL-escape titles by doubling quotes; locate the fixture DB by the same `BKLibrary-*.sqlite` glob production uses; root every path at PROJECT_ROOT and verify the resolved path before the first write, because a swapped path once planted a stray fixture inside the real Apple Books directory. Document how each fixture was derived in `docs/test_fixtures.md` in the same commit. Preserve intentionally-empty directories with a single `.gitkeep` at the leaf. Prefer extending `test_reader` over new personas unless a test needs isolation. After any fixture change, verify through the product: `python -m bookminder list recent --user <absolute fixture path>`.
- **B-28 — Fixture census freshness.** Never rely on a remembered census of what `test_reader` contains; earlier remembered censuses went stale when books were swapped. Query it instead: `sqlite3 "specs/apple_books/fixtures/users/test_reader/Library/Containers/com.apple.iBooksX/Data/Documents/BKLibrary/BKLibrary-fixture.sqlite" "SELECT ZTITLE, ZSTATE, ZISSAMPLE, ZREADINGPROGRESS FROM ZBKLIBRARYASSET"`. Know the one piece of lore: the zero-byte `401429854.epub` placeholder is "Growing Object-Oriented Software, Guided by Tests", the project's canonical known book, named in ORIGINAL_VISION.md.
- **B-29 — Real DB vs fixtures.** Explore Apple Books behavior read-only against a real database, because fixtures can only confirm what was built into them; when reality shows a new case worth capturing, copy it into the fixture. Specify any recency-window behavior with controlled time, because fixtures freeze time and the snapshot otherwise silently ages out of the window.
- **B-30 — Toolchain and environment.** Keep Python pinned `==3.13.*` in `pyproject.toml`, a pin rather than a permissive floor, because reproducibility across machines depends on one interpreter; the toolchain is uv + ruff + mypy on the setuptools backend, and ruff `target-version = "py312"` stays until the pinned ruff accepts py313. Run tests from the venv: `source .venv/bin/activate && pytest`; `uvx bookminder` fails because the package is unpublished, and bare `uv run` re-downloads CPython. Provision a fresh checkout, which has no `.venv`, with `uv venv && uv pip install -e ".[dev]"`. When ruff disagrees between shell and hook, compare `.pre-commit-config.yaml`'s pinned `rev:` against `ruff --version` in the venv. Keep `check-toml` in pre-commit; an invalid pyproject once passed an all-green run and broke the second machine.
- **B-31 — Repo maintenance principles.** Keep exactly one source of truth per concern, and make a migration delete the superseded file inside itself. Never invent identity metadata: the author is Pavol Vaskovic (pali@pali.sk); ask or leave blank. Put no untested causal claim into docs: if you assert X is required, remove X and show the failure first, and never document a command until you have run it and shown it working. Judge any document by whether it is referred back to and changes behavior on this project; retrospective meta-analysis docs fail both tests and the author calls them slop. Write README bash snippets without inline comments, because readers copy-paste them, and put the explanation in the prose above.
